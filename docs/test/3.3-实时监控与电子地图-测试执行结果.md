## 三、端到端联调逐条结果（真实 PostgreSQL 15 + Redis 7 + nginx 容器）

模块：[`backend/tests/e2e/test_monitor_e2e.py`](../../backend/tests/e2e/test_monitor_e2e.py)，
连接真实 Redis Stream 与真实 WebSocket 客户端（`websockets` 库），不经 ASGI 进程内模拟。

**执行前置**（缺一则整个模块 skip 或用例红，均已写进模块 docstring）：

| 前置项 | 值 | 原因 |
|--------|-----|------|
| `ALLOW_DEVICE_REPORT` | `true`（`.env.docker`） | 生产默认 `false`，上报端点会 404 |
| `DEVICE_REPORT_KEY` | `local-e2e-device-key` | 用例以 `X-Device-Key` 头模拟设备上报 |
| `OFFLINE_SCAN_ENABLED` | `false` | 心跳扫描会把用例间设备刷成 `offline`，统计卡片增量断言无法稳定；行为本身由 `tests/test_device_report.py` 覆盖，生产默认 `true` |
| `websockets` 库 | 宿主机 16.0（未入 `requirements.txt`） | 缺失时该组用例 `importorskip` 自动跳过 |

**M1 性能红线实测**（计划 §九 W6-D5「模拟器 → WS → 客户端帧延迟 P95 ≤ 2s，验收红线 3s」）：

```
[latency] n=10 p50=0.081s p95=0.111s max=0.111s
```

10 次「`POST /monitor/report` 发出 → WS 客户端收到对应 `alarm_new`」的端到端往返，
P50 0.081s、P95 0.111s、最大值 0.111s，无单帧超过 3s 红线。同套件上一轮全量重跑为 `p50=0.079s p95=0.126s max=0.126s`，两次均在设计目标 ≤2s 内。

## 四、执行期间发现并修复的缺陷

| # | 类型 | 现象 | 修复 | 守护手段 |
|---|------|------|------|----------|
| 1 | 测试基础设施缺陷（**真实生产影响**） | 会话 teardown 原顺序为「复位 → 删设备」，但复位要求设备物理状态已恢复：设备软删后用于正常化的上报返回 404，上报型报警因此**永远无法收敛**。手工清扫时打印 20 条复位失败 | `_cleanup` 顺序改为「上报 normal → 复位 → 删设备」，残余失败打印 `[warn]` 而不是静默吞掉 | 最后一轮结束后实测 `pending_alarm=0`、未收敛报警 `total=0`（第三节末尾）；`test_reset_requires_explicit_physical_evidence` |
| 2 | 部署环境 | `frontend/nginx.conf` 的 `/ws` 只是**预留代理**（未设长连接读超时，默认 60s 空闲即静默断开），且**完全没有 `/static/` 反代**：`/static/maps/*` 被 SPA history 回退规则吞成 `200 text/html`，浏览器侧表现为「底图不显示、实时推送静默失效」而无任何报错 | `/ws` 补 `proxy_read_timeout/proxy_send_timeout 3600s`，新增 `location /static/` 反代到后端；`docker compose build frontend` 并重建容器（旧镜像不生效） | `test_websocket_and_static_work_through_nginx`（走 `:80` 真实 nginx 而非直连 8000） |

| 4 | 测试假设错误（假阳性风险） | WS Ticket 用例断言收到 `pong`，实际收到上一用例残留的 `device_status`——扇出是异步的，新连接会看到在途事件 | `probe` 改为按 `type` 等待 `pong`（客户端本就按 type 分派），并在注释里说明在途事件属正常语义 | `test_ws_ticket_is_one_time_and_required`；`websocket.js` 的按类型分派契约 |
| 5 | 测试期望写错 | 统计卡片用例断言 `after.normal == before.normal + 1`，实际两台新设备上报后立即离开 normal，正确期望是 `== before.normal` | 修正断言并保留 `online == total - offline - retired` 口径校验 | `test_dashboard_counts_move_with_reports` |

| 7 | 前端跨版本回归 | 3.2 的 `ArchiveDetail.spec.js` 因 `SOURCE_META.alarm` 占位项被 3.3 真实数据源替换而失败；详情页引入 `el-tabs` + 路由跳转后，共享挂载骨架缺 router 即抛错 | 删除已失效的 `SOURCE_META.alarm` 占位与断言；`src/views/device/__tests__/mount.js` 增加 `createTestRouter()` 并由 `mountOptions()` 一并装 pinia + router（纯 store 用例仍各自 `setActivePinia`） | `views/device/__tests__/ArchiveDetail.spec.js`（5 条）与新 spec 同时全绿 |

## 五、未覆盖项与验收边界

**未覆盖（不可由本层测试证明，需人工或后续专项）**

1. **真实浏览器声光提示链路**：Chrome 自动播放策略要求用户手势，`Notification` 授权弹窗与 `AudioContext` 解锁无法在 jsdom 中验证。
   前端覆盖到 `alarmNotifier` 单测（分级选音、循环、降级、静音）+ 构建产物，**"演示时是否有声音"必须在浏览器里人工确认**（计划 §十.3 已声明这是策略而非缺陷）。
2. **Leaflet 实际渲染与拖拽流畅度**：jsdom 下无 canvas/布局，`utils/geo.js` 纯函数已单测，但 `CRS.Simple` 叠加、图标着色、markercluster 聚合视觉、拖拽掉帧均需人工。
3. **计划 §10.4-1 的 100 条/s 压测**：实际只做了 n=10 的单帧延迟基准（第三节）。模拟器支持 `--rate`，压测脚本入口在 `backend/scripts/device_simulator.py`，本轮未执行。
4. **计划 §10.4-2 的 1000 / 5000 点位地图压测**：E2E 只验证了「超过 limit 即切网格聚合且桶和等于 total」的正确性，未验证首屏 ≤2s 的性能结论。
5. **多级区域递归下的数据范围**：种子组织树只有 1 个根区域，`dept` 与 `all` 可见量相同（第三节第 15 项）。多级子树推送过滤由 SQLite 单测 `test_ws_data_scope.py` 与 3.2 的 `test_data_scope.py` 覆盖，未在真实 PostgreSQL 上展开。
6. **多 worker 水平扩展下的重复推送**：开发/联调均为单 worker。消费者名为 `{hostname}-{pid}-{uuid}` 的设计已实现，但未在 `WORKERS≥2` 下实测（依赖 nginx 容器真实多进程，超出本轮范围）。
7. **浏览器兼容性矩阵**（Chrome/Edge/Firefox 100+）未执行。

**计划偏离**（权威版本见 `docs/plan/3.3-实时监控与电子地图-开发计划.md` 第十五节，随计划一同入库）

1. WS 握手拒绝在 uvicorn 下表现为 **HTTP 403**（浏览器只见 `onclose(1006)`），`close(4401)` 状态码仅在 ASGI 层可断言（`test_ws_realtime.py`）；计划 §3.3 按 4401 描述。
2. 单次上报先广播 `device_status` 再广播 `alarm_new`（计划未规定顺序）；前端因此必须按 `type` 分派而非假定成对到达。
3. 平面图为**本地卷 + StaticFiles 匿名读**，未接 MinIO 预签名 URL（计划 C-2）；图片切片方案延期 P2（C-4）。
4. 轨迹导出改为前端 blob 下载（携带 Authorization 头），非计划 F-18 的 `window.open` + URL 带 token —— 避免令牌进 access_log 与浏览器历史。
5. 依赖版本高于计划锁定值：`pillow 12.3.0`（计划 10.3.0）、`pymupdf 1.28.2`（1.24.7）、`fakeredis 2.37.1`（2.23.2）、`echarts ^5.6.0`（^5.5.0）。
6. 测试 Redis 采用 §10.1 方案 A（`fakeredis`），未引入 `EventBus` 抽象层；`conftest.py` 的 fake client 已扩展为支持 `XADD/XRANGE/XGROUP`。
7. 端到端新增环境变量 `E2E_DEVICE_KEY`、`E2E_PUBLIC_URL`（默认 `http://localhost`，nginx 不可达时 skip）。

**验收边界（需在演示/验收说明中体现，非缺陷）**

- 复位的前置判定依赖 `last_report_at` 新鲜度（阈值 180s）+ `status==normal`；MQTT 未接入前，"物理状态已恢复"只能由值班员显式勾选 `physical_restored` 并承担审计留痕（OQ-2）。
- WS 权限快照在连接时计算，区域结构调整后需重连才生效（计划 §六.5 已知限制）。
- 消音是客户端全局态 + 单条服务端留痕的组合：`silence` 不改 `status`、重复调用不重复广播，全局静音存 localStorage、不跨端同步（OQ-4）。

## 六、复现方式

```bash
# 0) 依赖与镜像：requirements/package.json 变更后必须重建，否则容器内 ModuleNotFoundError
docker compose build backend frontend && docker compose up -d && docker compose ps
#    .env.docker 需含：ALLOW_DEVICE_REPORT=true / DEVICE_REPORT_KEY=local-e2e-device-key / OFFLINE_SCAN_ENABLED=false

# 1) 后端单元 + 集成（SQLite 内存库 + fakeredis）—— 期望 159 passed、48 skipped（48 条即未设 E2E_BASE_URL 的 e2e 用例）
cd backend && python -m pytest -v

# 2) 前端单元测试 —— 期望 19 files / 106 passed
cd frontend && npx vitest run

# 3) 前端生产构建
cd frontend && npm run build

# 4) 端到端回归（真实容器 + PostgreSQL + Redis Stream + nginx）
cd backend && E2E_BASE_URL=http://localhost:8000/api/v1 python -m pytest tests/e2e -v -s
#    期望 47 passed + 1 xfailed；控制台打印 [latency] ... 一行
#    可选：E2E_PUBLIC_URL=http://localhost:80 指定 nginx 入口（默认 http://localhost）

# 5) 演示/手工联调时用模拟器造数据（不经 HTTP，进程内直调上报服务）
cd backend && python scripts/device_simulator.py --rate 1 --scenario fire-alarm
```
