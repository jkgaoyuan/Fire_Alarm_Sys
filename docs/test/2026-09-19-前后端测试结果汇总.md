## 四、后端失败逐条根因

9 条失败**只有 6 个根因**，逐条如下（错误位置与信息均为实测原文）。

### A. 生产代码缺陷 —— `emergency_service.py` 缺 `update` import（3 条）

| # | 用例 | 错误 |
|---|------|------|
| 1 | `test_notifications.py::TestMarkAsRead::test_mark_single_as_read` | `app/services/emergency_service.py:467: NameError: name 'update' is not defined` |
| 2 | `test_notifications.py::TestMarkAsRead::test_mark_nonexistent_notifications` | 同上 |
| 3 | `test_notifications.py::TestNotificationConcurrency::test_concurrent_mark_read` | 同上 |

**根因**：`app/services/emergency_service.py` 第 14 行只导入了 `from sqlalchemy import select, func`，
而第 467 行（函数 `mark_notifications_as_read`，定义在第 449 行）直接使用 `update(...)`。

**⚠️ 影响面修正（详见第八节）**：该函数**没有任何生产调用方**，
`POST /api/v1/notifications/read-all` 端点自带一份内联实现且**实测返回 HTTP 200**。
因此这不是线上 500，而是**一处潜伏缺陷**（1 行 import 即可修）+ 一个无用 import。
修法：第 14 行补 `update`；顺带清理 `app/api/v1/notifications.py:19` 的无用导入。

### B. 测试自身缺 import（1 条）

| # | 用例 | 错误 |
|---|------|------|
| 4 | `test_notifications.py::TestMarkAsRead::test_cannot_mark_other_users_notifications` | `tests/test_notifications.py:169: NameError: name 'mark_notifications_as_read' is not defined` |

**根因**：该用例直接使用函数名却未在文件内导入（同文件 117/184/282 行都写了局部 import，唯独 169 行这一处漏了）。

### C. 测试与模型字段漂移（1 条）

| # | 用例 | 错误 |
|---|------|------|
| 5 | `test_emergency_fixtures.py::TestEmergencyTimeline::test_cascade_delete_timeline` | `TypeError: 'user_id' is an invalid keyword argument for EmergencyTimeline` |

**根因**：测试用 `EmergencyTimeline(user_id=...)` 构造，而该模型真实字段是 `operator_id`（`models/emergency.py:49`）。
与 P1-011 记录的同类漂移，**这次漂移的是测试而非生产代码**。

### D. SQLite DateTime 类型限制（2 条）

| # | 用例 | 错误 |
|---|------|------|
| 6 | `test_emergency_fixtures.py::TestEmergencyEventCreation::test_create_event_on_real_alarm` | `StatementError: (builtins.TypeError) SQLite DateTime type only accepts Python datetime and date objects as input.` |
| 7 | `test_emergency_fixtures.py::TestEmergencyEventCreation::test_false_alarm_no_event` | 同上 |

**根因**：测试向 DateTime 列传入了字符串。SQLite 方言不做隐式转换（PostgreSQL 会接受）。
**测试环境专属问题，生产不受影响。**

### E. 测试实参顺序传反（1 条）

| # | 用例 | 错误 |
|---|------|------|
| 8 | `test_emergency_fixtures.py::TestEmergencyTimeline::test_add_timeline_node` | `tests/test_emergency_fixtures.py:96: AssertionError: assert '1' == 'field_confirmed'` |

**根因**：`add_timeline_node` 的签名是 `(session, event_id, node_type: str, operator_id: int, ...)`，
而测试第 93 行调用为 `add_timeline_node(db_session, event.id, 1, "field_confirmed")`——
**后两个实参传反了**：`1` 进了 `node_type`，`"field_confirmed"` 进了 `operator_id`。
于是第 96 行 `node.node_type == "field_confirmed"` 读到的是 `'1'`。
**测试写法缺陷**，非生产代码问题。

### F. 测试访问惰性关系属性（1 条）

| # | 用例 | 错误 |
|---|------|------|
| 9 | `test_emergency_event.py::TestEmergencyEventCreation::test_create_event_on_real_alarm` | `sqlalchemy.exc.MissingGreenlet: greenlet_spawn has not been called; can't call await_only() here.` |

**根因**：测试在第 45 行执行 `assert event.timelines is not None`，
直接触碰 `EmergencyEvent.timelines` 这个惰性加载的 relationship，在 async 会话下触发隐式 IO。
**属于测试写法问题**（应改用 `await db_session.refresh(event, ["timelines"])` 或 `selectinload`），
**不是生产代码缺陷**。

## 八、关键发现：P1-010 影响面的实测复核

**背景**：`CLAUDE.md` 的待办 **P1-010** **原记录**为
「`POST /api/v1/notifications/read-all` **必然 500**。前端 `markNotificationsAsRead()` 正调它」。

⚠️ 本会话进行期间有**并发会话**在同一仓库工作，该条**已被先行更正**（更正方向与本报告一致）；
本节给出本会话**独立复核**的证据链，并补上两条此前未记录的证据。
**当前 `CLAUDE.md` 的 P1-010 已按本节结论回填完毕。**

**结论：该端点「必然 500」的判断不成立。** 证据链：

**① 端点自带内联实现，不调用出问题的那个函数。**
`app/api/v1/notifications.py:74` 的 `read_all_notifications()` 函数体内有自己的
`from sqlalchemy import update`（第 80 行）和自己的 `update(Notification)` 语句，
与 `emergency_service.mark_notifications_as_read()` 是完全独立的两份实现。

**② 该服务函数全仓库无生产调用方。**
全仓库检索 `mark_notifications_as_read` 只有 3 处命中：定义处、`notifications.py:19` 的
**未使用 import**、以及 `tests/test_notifications.py` 的 5 处测试调用。没有任何端点调用它。

**③ 容器实测（真实后端 + PostgreSQL）。**
`docker-compose.yml` 将 `./backend` 挂载为 `/app`，容器运行的即当前工作树代码（已核对容器内
`notifications.py:80` 确有该内联 import、`emergency_service.py:14` 确无 `update`）：

```
POST /api/v1/notifications/read-all   →  HTTP 200  {"code":200,"message":"已全部标记为已读"}
GET  /api/v1/notifications/unread-count →  HTTP 200  {"code":200,"data":{"unread_count":0}}
```

（验收时 admin 用户未读数为 0，该调用为**空操作**，未改动任何数据。）

**修正后的结论**：

| 项 | 原记录 | 实测修正 |
|----|--------|----------|
| 端点状态 | 必然 500 | **正常返回 200** |
| 缺陷性质 | 线上 500 | **潜伏缺陷**（服务函数无调用方） |
| 触发条件 | 用户点「全部已读」 | 仅当**未来有代码调用该服务函数**时 |
| 严重程度 | P1 | 建议降为 **P2**（1 行 import，且当前不可达） |

3 条 `test_notifications.py` 的红灯因此属于**「测试在测一个没人用的函数」**——
红灯真实，但它守的不是线上行为。修法仍值得做（补 1 行 import + 清理无用 import），
但不应再按「线上 500」的优先级排期。
