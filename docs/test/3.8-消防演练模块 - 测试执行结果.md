### 3.2 执行状态

❌ **因 Windows 终端编码问题无法执行**

问题描述：
- 复制粘贴或 PowerShell 重定向导致测试文件出现非法 Unicode 字符（U+E178, U+E1D7, U+2033 等）
- pytest 在 AST 解析阶段即报 SyntaxError，无法收集测试用例
- 同一文件多次尝试均因相同根因失败

受影响文件：
- `backend/tests/e2e/test_drill_e2e.py`（损坏次数 > 5）

### 3.3 临时规避方案

建议替代方案：
1. **手动测试验证**: 通过 Postman/浏览器完整回归「创建演练→开始执行→完成演练→评估打分→导出报告」
2. **CI/CD 自动化**: Linux 环境运行（Linux 终端无此编码问题）
3. **测试代码纯 ASCII**: 避免中文注释和字符串，仅保留英文 docstring

### 4.2 §十五「实现偏离」回填

**本章节原文为空，现补充如下：**

#### 偏离项 #1：trigger-alarm 端点缺失

- **计划要求** (§六 B3): "提供 `/api/v1/drills/{id}/trigger-alarm` 端点，由值班员发起模拟报警触发联动预案"
- **实际情况**: 该端点**未实现**。原因：
  1. 前端需求变更后取消“模拟报警”按钮（UI 设计稿移除）
  2. 现有 `drill/events/{id}/execute` 已满足演练启动场景
  3. 若未来需联动预案自动触发报警，可在 AlarmService.raise_alarm() 增加 is_drill=True 逻辑
- **影响评估**: 低优先级（无前端入口）
- **建议**: 暂不实施；如产品确需则追加 ticket

#### 偏离项 #2：数据权限过滤缺失

- **计划要求** (§六 B4): "演练列表按 created_by/org_id 过滤；首版按创建人可见，主管可见全部"
- **实际情况**: CRUD 端点**未实现组织/创建人过滤**，所有用户可见全部演练数据
- **影响评估**: 高（多租户隔离风险）
- **建议**: 
  1. 在 DrillService.get_drills() 增加 visible_org_ids(db, user) + scope_by_org()
  2. 参考 inspection/repair 模块已有 data scope 模式

#### 偏离项 #3：评估 upsert 语义不一致

- **计划要求** (§六 B4 要点 4): "重复提交则更新（UPSERT）"
- **实际情况**: SQLAlchemy 唯一约束导致第二次 POST 抛 DuplicateKeyError，返回 400
- **影响评估**: 中（用户误操作会报错，但不影响数据一致性）
- **建议**: 
  1. 捕获 IntegrityError 后改用 session.merge() 或 UPDATE
  2. 或在前端提示“已在 X 天前评估，无法重复提交”

#### 偏离项 #4：get_active_drill 未实现

- **计划要求** (§六 B2): "演练执行中查询已发布且未开始的演练信息（检查参数是否齐备）"
- **实际情况**: `/api/v1/drills/{id}/context` **未实现**
- **影响评估**: 中（前端无法提前校验演练准备度）
- **建议**: 
  1. 实现简单 GET /drills/{id}?include_missing=true
  2. 或直接在 DetailDialog.vue 的 drilled 方法里合并校验逻辑（推荐）
