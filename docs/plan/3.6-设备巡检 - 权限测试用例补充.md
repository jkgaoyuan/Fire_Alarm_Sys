#### **TC-PERM-004: 数据范围过滤 - 维保人员只看责任人是自己的任务**

> ⚠️ **2026-09-14 更正。** 原用例名与参数写的是「仅看本部门及子部门设备 / `("maintainer", "dept")`
> / 维保人员只看本部门」，与 `3.6-设备巡检-开发计划.md`「后端技术要点」第 5 条
> （数据权限）「维保人员默认只看**责任人为自己**的任务」
> 「维保人员默认只看**责任人为自己**的任务」**互相矛盾**，且与实现不符。
>
> **实现口径**（`inspection_service.apply_task_data_scope`）：
>
> | data_scope | 任务域锚点 |
> |------------|-----------|
> | `all` | 不过滤 |
> | `self` | `InspectionTask.responsible_user_id == user.id`（**责任人**，不是录入人，也不是本部门） |
> | `dept` | `plan.org_id` 落在本部门子树内的任务 |
>
> 该函数开头专门写了注释说明**刻意不复用** `user_service.apply_data_scope`，
> 原因正是「任务的归属是 `responsible_user_id`」——与 DEC-021 对设备、
> DEC-012 对报警属同一口径：**每个域自己决定 `self` 锚在哪**。
>
> 另一个错误：原断言引用 `task["org_id"]`，而 `InspectionTaskResponse`
> **没有 `org_id` 字段**（任务表既无 `org_id` 也无 `created_by`），照抄会直接 KeyError。

```python
@pytest.mark.parametrize("role,expected", [
    ("chief", "all"),      # 主管（data_scope=all）可查看所有任务
    ("maintainer", "self"),  # 维保人员（data_scope=self）只看责任人 = 自己
])
def test_data_scope_filtering_on_tasks(
    client: TestClient, db: Session, role: str, expected: str,
    get_token_by_role: dict[str, str], inspection_plan_with_multiple_orgs,
    responsible_user_id_of_maintainer: int,
):
    """巡检任务按 data_scope 过滤：all 不过滤；self 锚 responsible_user_id"""
    token = get_token_by_role[role]
    response = client.get(
        "/api/v1/inspection-tasks",
        params={"page": 1, "page_size": 20},
        headers={"Authorization": f"Bearer {token}"}
    )

    assert response.status_code == 200
    tasks = response.json()["data"]["items"]

    if expected == "all":
        assert len(tasks) > 0
    else:
        # 注意断言的是 responsible_user_id，不是 org_id（响应里没有该字段）
        assert all(
            task["responsible_user_id"] == responsible_user_id_of_maintainer
            for task in tasks
        )
```

**覆盖点**: DEC-004 数据权限规范 + 各域自定 `self` 锚点（DEC-012 / DEC-021）

#### **TC-PERM-005: 巡检记录 createdBy 过滤（self 范围）**

```python
def test_inspection_records_created_by_filter(
    client: TestClient, db: Session, get_maintainer_token: str,
    maintenance_user: User  # 维保人员账户
):
    """维保人员只能看到 created_by=self 的巡检记录"""
    # 创建两条记录：一条为自己创建，一条为他人创建
    my_record = create_inspection_record(created_by=maintenance_user.id)
    other_record = create_inspection_record(created_by=some_other_user.id)
    
    response = client.get(
        "/api/v1/inspection-records",
        headers={"Authorization": f"Bearer {get_maintainer_token}"}
    )
    
    records = response.json()["data"]["items"]
    assert all(rec["created_by"] == maintenance_user.id for rec in records)
    assert not any(rec["id"] == other_record.id for rec in records)
```

**覆盖点**: DEC-004 `created_by` 字段作用

> ⚠️ **本条规格当前未实现（2026-09-14 实测）—— 保留为待办，不作为已通过项。**
>
> `GET /inspection-records` **没有任何数据范围过滤**：该端点只有权限码门禁
> （`require_permission("inspection:view")`），详情见
> `app/api/v1/inspection.py` 的 `get_inspection_records`。实测维保员账号
> 返回**全部** 16 条记录，含 `created_by` 为他人的。
>
> 顺带，这里的口径本身也要重新想：`created_by` 是**录入人**。
> 按上面第三处「各域自定锚点」的结论，巡检记录的「归属」更可能是
> `inspected_by`（实际巡检人）而非 `created_by`（提交动作的执行者）——
> 参照任务域用 `responsible_user_id` 而非 `created_by` 的理由。
> 定口径时要连同 FR-036「记录归档，支持按设备/人员/时间筛选查询」一起看：
> 归档类数据的可见性未必要按人收窄。

### 3.1 Vue 组件权限指令测试

```javascript
// frontend/src/views/inspection/__tests__/Plan.spec.js
import { mount } from '@vue/test-utils'
import PermissionDirective from '@/directives/permission'
import Plan.vue from '../Plan.vue'

describe('Plan.vue v-permission', () => {
  it('should hide edit buttons for duty officer role', () => {
    const wrapper = mount(Plan.vue, {
      global: {
        directives: { permission: PermissionDirective },
        mocks: {
          $route: { meta: { roles: ['duty_officer'] } }
        }
      }
    })
    
    // 编辑按钮应隐藏（display:none）
    expect(wrapper.find('[data-testid="edit-btn"]').element).toHaveStyle('display: none')
  })
  
  it('should show create button for chief role', () => {
    const wrapper = mount(Plan.vue, {
      global: {
        directives: { permission: PermissionDirective },
        mocks: {
          $route: { meta: { roles: ['chief'] } }
        }
      }
    })
    
    // 创建按钮应可见
    expect(wrapper.find('[data-testid="create-btn"]').exists()).toBe(true)
  })
})
```
