## 2. 开发目标与验收标准

### 2.1 核心目标
1. 三类角色（消防值班员 / 维保人员 / 消防主管）可独立登录系统，看到不同的菜单与数据范围。
2. Access Token 过期前自动刷新，用户无感知。
3. 连续 5 次登录失败锁定账户 30 分钟，并记录登录日志。
4. 后端提供统一的权限校验依赖（`get_current_user` + `require_permission`）。

### 2.2 验收标准
- [ ] 三类角色登录后，`/api/v1/users/me/menus` 返回各自可见菜单，前端侧边栏正确渲染。
- [ ] 消防主管可访问"系统管理"菜单，其他角色不可见且接口返回 403。
- [ ] 登录成功后 Redis 中存在 Token 白名单；登出后白名单清除。
- [ ] Access Token 1 小时过期，Refresh Token 7 天过期；前端在 Access Token 过期前 5 分钟自动刷新。
- [ ] 同一账户连续输错 5 次密码后，第 6 次返回"账户已锁定，请 30 分钟后重试"。
- [ ] 设备列表接口按用户数据范围过滤（主管看全部、值班员看本部门、默认看本人）。

## 3. 数据库设计

基于 PRD 4.2 节核心表结构，按开发顺序细化如下：

### 3.1 用户与权限表（第一阶段必须）

```sql
-- 1. 用户表
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,  -- bcrypt, cost=12
    real_name VARCHAR(50),
    phone VARCHAR(20),
    email VARCHAR(100),
    org_id BIGINT REFERENCES organizations(id),
    data_scope VARCHAR(20) DEFAULT 'self', -- all / dept / self
    status VARCHAR(20) DEFAULT 'active',   -- active / locked / disabled
    login_fail_count INT DEFAULT 0,
    locked_until TIMESTAMPTZ,
    last_login_at TIMESTAMPTZ,
    last_login_ip INET,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. 角色表（预置 3 条 + 支持自定义）
CREATE TABLE roles (
    id BIGSERIAL PRIMARY KEY,
    role_code VARCHAR(50) UNIQUE NOT NULL, -- duty_officer / maintainer / chief
    role_name VARCHAR(50) NOT NULL,
    description TEXT,
    is_builtin BOOLEAN DEFAULT FALSE,      -- 内置角色不可删除
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. 用户角色关联（禁止级联删除）
CREATE TABLE user_roles (
    user_id BIGINT REFERENCES users(id) ON DELETE RESTRICT,
    role_id BIGINT REFERENCES roles(id) ON DELETE RESTRICT,
    PRIMARY KEY (user_id, role_id)
);

-- 4. 权限表（菜单 / 按钮 / API）
CREATE TABLE permissions (
    id BIGSERIAL PRIMARY KEY,
    perm_code VARCHAR(100) UNIQUE NOT NULL,  -- device:view, alarm:confirm
    perm_name VARCHAR(100),
    perm_type VARCHAR(20),  -- menu / button / api
    parent_id BIGINT REFERENCES permissions(id),
    route_path VARCHAR(200),   -- 前端路由路径（perm_type=menu 时有效）
    component VARCHAR(200),    -- 前端组件路径
    icon VARCHAR(50),          -- 菜单图标
    sort_order INT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 5. 角色权限关联
CREATE TABLE role_permissions (
    role_id BIGINT REFERENCES roles(id) ON DELETE RESTRICT,
    perm_id BIGINT REFERENCES permissions(id) ON DELETE RESTRICT,
    PRIMARY KEY (role_id, perm_id)
);

-- 6. 组织架构表（数据权限依赖）
CREATE TABLE organizations (
    id BIGSERIAL PRIMARY KEY,
    parent_id BIGINT REFERENCES organizations(id),
    org_name VARCHAR(100) NOT NULL,
    org_type VARCHAR(20),  -- building / floor / zone
    sort_order INT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 7. 登录审计日志表
CREATE TABLE login_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT REFERENCES users(id),
    username VARCHAR(50),
    login_type VARCHAR(20),  -- password / refresh
    ip_address INET,
    user_agent TEXT,
    device_type VARCHAR(50), -- desktop / mobile / tablet
    device_os VARCHAR(50),   -- Windows / macOS / iOS / Android
    browser VARCHAR(50),     -- Chrome / Firefox / Edge
    status VARCHAR(20),      -- success / fail / locked
    fail_reason VARCHAR(100),-- password_error / account_locked / token_invalid
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 索引
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_status ON users(status);
CREATE INDEX idx_user_roles_user ON user_roles(user_id);
CREATE INDEX idx_role_permissions_role ON role_permissions(role_id);
CREATE INDEX idx_permissions_parent ON permissions(parent_id);
CREATE INDEX idx_login_logs_user ON login_logs(user_id, created_at);
CREATE INDEX idx_login_logs_created ON login_logs(created_at);
```

### 4.3 核心模块开发任务

#### 任务 B-1：项目脚手架与数据库连接（W1-D1~D2）
- [ ] `core/config.py`：读取 `.env`，定义 `Settings`（数据库 URL、Redis URL、JWT 密钥、Token 有效期）。
- [ ] `db/session.py`：创建 `async_engine` + `AsyncSessionLocal`。
- [ ] `models/base.py`：声明式基类 `Base`，内置 `id`、`created_at`、`updated_at`。
- [ ] Alembic 初始化，生成第一张迁移脚本（含 `users`、`roles`、`permissions` 等）。
- [ ] `Dockerfile`：多阶段构建，内置大陆镜像源（清华/阿里）。

#### 任务 B-2：安全与 JWT 工具（W1-D2~D3）
- [ ] `core/security.py`：
  - `verify_password(plain, hashed) -> bool`
  - `get_password_hash(plain) -> str`
  - `create_access_token(data, expires_delta)` / `create_refresh_token(data, expires_delta)`
  - `decode_token(token) -> dict`（捕获 `ExpiredSignatureError` / `JWTError`）
- [ ] 密码策略：最小 8 位，包含字母 + 数字。

#### 任务 B-3：登录与 Token 管理 API（W1-D3~D4）
- [ ] `POST /api/v1/auth/login`
  - 流程：查用户 → 校验状态（是否锁定）→ bcrypt 校验密码 → 失败计数 +1 / 清零 → 生成双 Token → 写入 Redis 白名单（`token_whitelist:{user_id}:{jti}`）→ 记录登录日志。
  - 锁定逻辑：`login_fail_count >= 5` 时设置 `locked_until = NOW() + 30min`。
  - **响应设计（登录成功）**：
    ```json
    {
      "access_token": "eyJhbG...",
      "token_type": "bearer",
      "expires_in": 3600,
      "user": { "id": 1, "username": "admin", "real_name": "管理员", "roles": ["chief"] }
    }
    ```
    - **注意**：`access_token` 返回给前端存入 localStorage；**`refresh_token` 不返回在响应体中**，由后端通过 `Set-Cookie: refresh_token=xxx; HttpOnly; Secure; SameSite=Strict; Max-Age=604800` 下发。
  - **响应设计（登录失败）**：
    ```json
    {
      "code": 4001,
      "message": "密码错误",
      "data": { "remaining_attempts": 3 }
    }
    ```
    或锁定状态：
    ```json
    {
      "code": 4003,
      "message": "账户已锁定",
      "data": { "locked_until": "2026-09-07T12:30:00+08:00" }
    }
    ```
- [ ] `POST /api/v1/auth/refresh`
  - **请求方式**：前端不携带任何 Token 请求头，由浏览器自动通过 httpOnly Cookie 发送 `refresh_token`。
  - 后端从 Cookie 中读取 Refresh Token → 校验签名与 Redis 白名单 → 生成新 Access Token → 若启用 Refresh Token 轮换，则同时生成新 Refresh Token 并通过 `Set-Cookie` 下发 → 返回 `{ access_token, expires_in }`。
- [ ] `POST /api/v1/auth/logout`
  - 当前 Access Token 加入 Redis 黑名单（`token_blacklist:{jti}`），有效期与 Token 剩余时间一致。
  - 删除 Redis 中该用户的 Token 白名单记录。
  - **响应头清除 Refresh Token Cookie**：`Set-Cookie: refresh_token=; HttpOnly; Secure; SameSite=Strict; Max-Age=0; Path=/`
  - 前端同步清除 localStorage 中的 Access Token。

#### 任务 B-4：统一鉴权依赖（W1-D4~D5）
- [ ] `core/dependencies.py`：
  - `get_current_user(token: str = Depends(oauth2_scheme)) -> User`
    - 解码 Access Token → 查黑名单 → 查用户 → 返回 User ORM 对象。
  - `require_permission(perm_code: str)`：返回依赖函数，校验当前用户是否拥有该权限码，否则 403。
  - `get_data_scope_filter(user: User) -> list[int]`：根据用户 `data_scope` 返回可访问的 `org_id` 列表（递归查子部门）。

#### 任务 B-5：用户信息与菜单 API（W1-D5~W2-D1）
- [ ] `GET /api/v1/users/me`
  - 返回当前用户基本信息 + 所属组织 + 角色列表。
- [ ] `GET /api/v1/users/me/menus`
  - 查询用户所有角色的权限，筛选 `perm_type='menu'`，按 `parent_id` + `sort_order` 构建树形菜单。
  - 返回 Vue Router 可用格式： `{path, name, component, meta: {title, icon}, children}`。
- [ ] `GET /api/v1/users/me/permissions`
  - 返回当前用户所有权限码列表（`['device:view','alarm:confirm',...]`），供前端按钮级权限控制（`v-permission` 指令）。

#### 任务 B-6：角色管理 API（W2-D1~D3）

#### 任务 F-1：项目脚手架与 Axios 封装（W1-D1~D2）
- [ ] Vite 初始化，配置 `@` 别名、`sass` 预处理器、Element Plus 自动导入。
- [ ] `utils/request.js`：
  - **请求拦截器（核心）**：
    1. 自动附加 `Authorization: Bearer {access_token}`。
    2. **主动刷新检查**：解析 Access Token 的 `exp` 字段，若距离过期小于 5 分钟（300 秒），且当前不在刷新过程中，则先调用 `/auth/refresh` 获取新 Access Token，再发送原请求。
  - **响应拦截器（兜底）**：
    - 401 且非刷新接口 → 说明主动刷新可能遗漏或失败，尝试一次静默刷新。
    - 刷新成功 → 更新 Access Token 并重试原请求；刷新失败 → 清除 Token 跳转登录页。
    - 403 → Element Plus `ElMessage.error('无权限访问')`，可跳转 403 页面。
  - **并发刷新控制**：使用单一 Promise 缓存模式。当多个请求同时发现 Token 即将过期时，仅第一个请求触发刷新，其余请求共享该 Promise，刷新完成后统一获取新 Token。
    ```javascript
    // 伪代码
    let refreshingPromise = null;
    
    function refreshToken() {
      if (!refreshingPromise) {
        refreshingPromise = authApi.refresh()
          .then(res => {
            setToken(res.access_token);
            return res.access_token;
          })
          .catch(err => {
            // 刷新失败，清除状态跳转登录
            clearToken();
            window.location.href = '/login';
            throw err;
          })
          .finally(() => {
            refreshingPromise = null;
          });
      }
      return refreshingPromise;
    }
    
    request.interceptors.request.use(async (config) => {
      const token = getToken();
      if (token && isTokenExpiringSoon(token, 300)) {
        const newToken = await refreshToken();
        config.headers.Authorization = `Bearer ${newToken}`;
      } else if (token) {
        config.headers.Authorization = `Bearer ${token}`;
      }
      return config;
    });
    ```

    ```javascript
    // 伪代码
    router.beforeEach(async (to, from, next) => {
      if (whiteList.includes(to.path)) return next();
      const token = getToken();
      if (!token) return next('/login');
      
      const permStore = usePermissionStore();
      if (!permStore.isRoutesLoaded) {
        await permStore.generateRoutes();
      }
      
      // 含参数路由（如 /device/1）按父路由路径校验
      const checkPath = to.matched[0]?.path || to.path;
      const hasPermission = permStore.flatMenuPaths.includes(checkPath) || to.path === '/';
      if (hasPermission) return next();
      return next('/403');
    });
    ```

### 10.3 错误码规范（本项目统一）

| 错误码 | 含义 | 场景 | 前端处理 |
|--------|------|------|---------|
| 200 | 成功 | 通用 | 正常消费 data |
| 400 | 参数校验失败 | 请求参数非法 | `ElMessage.warning(message)` |
| 401 | 未认证 | Token 过期/无效/未登录 | 清除 Token 跳转登录页 |
| 403 | 无权限 | 权限不足 | `ElMessage.error('无权限访问')`，可跳转 403 页面 |
| 404 | 资源不存在 | URL 或 ID 错误 | `ElMessage.error('资源不存在')` |
| 4001 | 密码错误 | 登录密码不匹配 | 登录页展示，消费 `data.remaining_attempts` |
| 4003 | 账户已锁定 | 连续失败达到上限 | 登录页展示锁定倒计时，消费 `data.locked_until` |
| 4004 | 账户已禁用 | 用户状态 disabled | 登录页展示"账户已被禁用，请联系管理员" |
| 500 | 服务器内部错误 | 通用 | `ElMessage.error('服务器繁忙，请稍后重试')` |

- 响应格式统一遵循 PRD 5.9 节：`{ code, message, data, timestamp }`
- 前端 Axios 响应拦截器按 `code` 分类处理，4001/4003/4004 由登录页组件消费，其他由全局拦截器统一提示

### 10.4 关键设计决策

- **Token 白名单 vs 黑名单**：选择白名单（登录时写入 Redis，登出删除）+ 黑名单（登出时写入，用于 Access Token 提前失效）混合方案，兼顾安全与性能。
- **Refresh Token 是否轮换**：本次不轮换（简化实现），生产环境可升级为每次刷新下发新 Refresh Token，旧 Token 作废。
- **数据范围缓存**：`dept` 范围的子部门 ID 列表缓存到 Redis Key `user_dept_scope:{user_id}`，TTL 1 小时，部门结构调整时手动清除。
- **与 PRD 的差异说明（须同步更新 PRD）**：
  - `/api/v1/auth/refresh`：PRD 5.1 节要求请求体携带 `{refresh_token}`，本计划改为**完全由后端 httpOnly Cookie 承载**（更安全）。需在 PRD 中同步更新该接口的请求体为"无"，并注明 Cookie 方式。
  - 业务表 `created_by` 字段：PRD 4.2 节核心表结构未包含该字段，本计划要求所有业务表统一追加，用于 `data_scope='self'` 过滤。需在 PRD 数据模型章节同步补充。
