## 三、总体设计

### 3.1 数据流

```
报警产生（alarms.status='pending'）
        │
        ├── 5 分钟内值班员确认 ──▶ confirmAlarm()
        │                         ├── false_alarm ──▶ status='false_alarm'
        │                         └── real ──▶ status='confirmed' ──▶ create_emergency_event()
        │                                                           ├── insert timeline 'confirm'
        │                                                           ├── WS 推送 event_new
        │                                                           └── 自动/手动流转至 'processing'
        │
        └── 5 分钟超时 ──▶ escalation_scan() ──▶ 系统内通知主管 + timeline 'escalation'
                                          └── （可选）3.10 邮件通知

事件处置中 ──▶ 人员签到/上传照片/时间节点 ──▶ timeline 追加
        └── 处置完成 ──▶ resolve/close ──▶ 生成 PDF 报告
```

### 3.2 报警状态机与事件状态机关系

| 阶段 | `alarms.status` | `emergency_events.status` | 说明 |
|------|-----------------|---------------------------|------|
| 报警产生 | `pending` | 无 | 联动 3.4 自动执行 |
| 确认真实火警 | `confirmed` | `processing` | 事件创建 |
| 处置中 | `processing` | `processing` | 时间轴追加 |
| 处置完成 | `resolved` | `resolved` | 报警收敛，事件关闭 |
| 误报 | `false_alarm` | 无 | 不创建事件 |
| 强制关闭 | `closed` | `closed` | 主管可关闭长期未决事件 |

> **设计原则**：`alarms` 状态机表达"报警生命周期"，`emergency_events` 状态机表达"应急处置生命周期"。3.3 已实现报警侧状态机，本计划不重复，仅在其上扩展事件实体。

### 3.3 5 分钟超时升级机制

- 使用 FastAPI lifespan `asyncio` 后台任务，每 60 秒扫描一次 `alarms` 表。
- 命中条件：`status='pending'`、`is_drill=false`、`pending_since` 距当前时间 ≥ 5 分钟、且未生成过升级通知。
- 去重：在 `emergency_timelines` 中插入 `node_type='escalation'` 作为已升级标记，或专用 `alarm_escalations` 表（本计划选 timeline 标记，避免多表）。
- 通知：生成一条系统通知（`notifications` 表），主管角色用户右上角红点 + WS 推送 `notification_new`。

### 3.4 时间轴节点类型

| `node_type` | 触发点 | 可附加内容 |
|-------------|--------|-----------|
| `alarm` | 报警产生/事件创建 | 报警 ID、设备信息 |
| `confirm` | 确认真实火警 | 确认人、确认结论 |
| `linkage` | 联动执行完成 | 联动日志 ID、动作结果 |
| `escalation` | 超时升级 | 升级原因 |
| `evacuate` | 疏散完成 | 时间、备注 |
| `control` | 火情控制 | 时间、备注 |
| `check_in` | 人员签到 | 用户、GPS、时间 |
| `photo` | 现场照片 | 图片 URL |
| `complete` | 处置完成 | 总结 |

### 4.4 模型骨架

```python
# app/models/emergency.py
class EmergencyEvent(Base):
    __tablename__ = "emergency_events"
    alarm_id: Mapped[int] = mapped_column(ForeignKey("alarms.id"), unique=True, index=True)
    event_no: Mapped[str] = mapped_column(String(50), unique=True)
    status: Mapped[str] = mapped_column(String(20), default="processing")
    started_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), default=func.now())
    resolved_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
    closed_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
    closed_by: Mapped[Optional[int]] = mapped_column(ForeignKey("users.id"), nullable=True)
    summary: Mapped[Optional[str]] = mapped_column(Text, nullable=True)

class EmergencyTimeline(Base):
    __tablename__ = "emergency_timelines"
    event_id: Mapped[int] = mapped_column(ForeignKey("emergency_events.id"), index=True)
    node_type: Mapped[str] = mapped_column(String(50))
    node_title: Mapped[Optional[str]] = mapped_column(String(100))
    description: Mapped[Optional[str]] = mapped_column(Text)
    operator_id: Mapped[Optional[int]] = mapped_column(ForeignKey("users.id"))
    operated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), default=func.now())
    attachments: Mapped[list[dict]] = mapped_column(JSONB, default=list)
```

**请求体扩展（与 3.3 兼容）：**
```json

  "confirm_result": "real",
```

1. 更新 `alarms.status='confirmed'`。

### 后端技术要点

1. **事件创建必须在报警确认事务内**：确认成功即事件存在，避免确认后服务崩溃导致事件丢失。
2. **超时扫描幂等**：同一报警只生成一次 `escalation` timeline 节点，避免重复通知。
3. **数据权限**：事件列表按关联报警的 `org_id` 过滤；`self` 范围降级为 `dept`（同 3.3 报警）。
4. **PDF 生成**：首版同步生成，限制 ≤100 页；超大报告返回 202 并提示"请使用 3.9 异步导出"。
5. **通知未读数**：前端右上角轮询或 WS 推送；轮询间隔 30 秒作为兜底。

## 十一、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| `reportlab` 镜像构建失败 | PDF 导出不可用 | 备选 HTML 打印或 `weasyprint`；验收时至少有一种可用 |
| 超时扫描任务随服务重启漏扫 | 主管未收到升级通知 | 扫描基于 `pending_since` 时间戳，不依赖任务状态；启动即全量扫 |
| 同一报警多次创建事件 | 数据异常 | `emergency_events.alarm_id` 唯一约束 + 确认接口内事务 |
| 通知中心与 3.10 渠道配置冲突 | 重复开发 | 通知表设计预留 `module`/`ref_id`，3.10 直接复用 |
| 大报告同步导出阻塞 worker | 服务无响应 | 限制 100 页；超出走 3.9 异步导出 |
