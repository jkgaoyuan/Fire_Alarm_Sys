**设备状态枚举：** `normal`（正常）、`alarm`（报警）、`fault`（故障）、`shield`（屏蔽）、`offline`（离线）、`retired`（已退役）

**设备退役流程（关键约束）：**
1. 前端删除按钮文案改为「退役」。
2. 点击后设备 `status` 变更为 `retired`，`is_deleted` 保持 `FALSE`。
3. 设备列表默认过滤 `status = 'retired'`（除非勾选"显示已退役"）。
4. 关联的报警、巡检、维修记录**必须保留**，不可级联删除。

**权限矩阵：**

| 角色 | 设备档案权限 |
|------|-------------|
| 消防值班员 | `device:view` — 查看 |
| 维保人员 | `device:view`、`device:repair` — 查看、维修记录 |
| 消防主管 | `device:view`、`device:create`、`device:update`、`device:retire`、`device:delete` — 增删改查/退役/物理删除 |

> **`device:repair` 使用场景说明：** 该权限码控制维保人员在设备详情页中「维修记录」页签的可见性与可操作范围。在设备档案核心 API 中不直接作为路由权限，而在维修工单模块（3.7 FR-038 ~ FR-042）中作为功能权限使用。

### 2.2 SQLAlchemy 模型定义（后端参考）

```python
# app/models/device_type.py
class DeviceType(Base):
    __tablename__ = "device_types"

    type_code: Mapped[str] = mapped_column(String(50), unique=True, nullable=False)
    type_name: Mapped[str] = mapped_column(String(50), nullable=False)
    category: Mapped[Optional[str]] = mapped_column(String(20), nullable=True)
    attribute_schema: Mapped[dict] = mapped_column(JSONB, default=dict, nullable=False)
    icon_url: Mapped[Optional[str]] = mapped_column(String(500), nullable=True)

    devices: Mapped[List["Device"]] = relationship("Device", back_populates="device_type")


# app/models/device.py
class Device(Base):
    __tablename__ = "devices"

    device_code: Mapped[str] = mapped_column(String(100), unique=True, nullable=False)
    device_name: Mapped[str] = mapped_column(String(100), nullable=False)
    type_id: Mapped[Optional[int]] = mapped_column(
        ForeignKey("device_types.id"), nullable=True
    )
    org_id: Mapped[Optional[int]] = mapped_column(
        ForeignKey("organizations.id"), nullable=True
    )
    manufacturer: Mapped[Optional[str]] = mapped_column(String(100), nullable=True)
    model: Mapped[Optional[str]] = mapped_column(String(100), nullable=True)
    brand: Mapped[Optional[str]] = mapped_column(String(50), nullable=True)
    spec: Mapped[Optional[str]] = mapped_column(String(100), nullable=True)
    install_date: Mapped[Optional[date]] = mapped_column(Date, nullable=True)
    warranty_expire_date: Mapped[Optional[date]] = mapped_column(Date, nullable=True)
    maintain_cycle: Mapped[Optional[int]] = mapped_column(Integer, nullable=True)
    status: Mapped[str] = mapped_column(String(20), default="normal", nullable=False)
    map_x: Mapped[Optional[Decimal]] = mapped_column(DECIMAL(10, 2), nullable=True)
    map_y: Mapped[Optional[Decimal]] = mapped_column(DECIMAL(10, 2), nullable=True)
    attributes: Mapped[dict] = mapped_column(JSONB, default=dict, nullable=False)
    is_deleted: Mapped[bool] = mapped_column(Boolean, default=False, nullable=False)
    created_by: Mapped[Optional[int]] = mapped_column(
        ForeignKey("users.id"), nullable=True
    )

    device_type: Mapped[Optional["DeviceType"]] = relationship(
        "DeviceType", back_populates="devices"
    )
    org: Mapped[Optional["Organization"]] = relationship(
        "Organization", back_populates="devices"
    )
    creator: Mapped[Optional["User"]] = relationship("User")
```

> **模型类型说明：** 上述 `Mapped[int]` 在 SQLAlchemy 2.0 中默认映射为 `INTEGER`。若项目后续统一将 `Base.id` 升级为 `BigInteger`，则设备表外键（`type_id`、`org_id`、`created_by`）需同步显式指定 `mapped_column(BigInteger, ForeignKey(...))` 以保持与数据库 `BIGINT` 一致。当前计划的数据库 DDL 统一使用 `BIGSERIAL`/`BIGINT`，Alembic 迁移脚本需显式声明 `sa.BigInteger()` 以匹配。

> **注意：** `Organization` 模型需补充 `devices` 反向关系。

### 后端技术要点

1. **数据权限过滤：** 列表查询必须接入数据范围过滤：
   - `all` — 不过滤
   - `dept` — `org_id IN (用户 org_id 及子部门)`
   - `self` — **降级为 `dept`**（2026-09-14 修订，见 DEC-021）

   > ⚠️ **本行原为「`self` — `created_by = 用户 id`」，2026-09-14 已修订。**
   >
   > 设备是**组织的资产**，不是录入人的私产；`created_by` 是「谁录的档案」，
   > 与「谁该看/该修/该管这台设备」无关。按建档人过滤的实测后果：维保员
   > （`data_scope='self'`，设备由管理员录入）在设备档案页看到 **0 台**，
   > 详情/历史/轨迹一律 404 —— 而设备维保恰是这个角色的本职工作。
   >
   > 实现落在 `device_service.apply_device_data_scope`（不再复用
   > `user_service.apply_data_scope`，后者如今已无调用方）。
   > 这与 DEC-012（alarms 的 `self` 降级为 `dept`）、
   > `apply_task_data_scope`（任务锚 `responsible_user_id`）、
   > `repair_service.repair_scope_condition`（工单锚报修/维修/验收/创建）
   > 属于同一口径：**每个域自己决定 `self` 锚在哪，锚不住就降级 dept**。
   >
   > 受影响用例：`test_device_permission.py` 的
   > `test_data_scope_self_falls_back_to_dept`（原名
   > `test_data_scope_self_limits_to_creator`，断言已改写）；
   > `test_device_scope.py` 的 `self_user` 补了部门（原先无部门，
   > 降级后会因「空部门」而非「不在范围内」通过，测不到真正的边界）。

2. **退役与删除区分：**
   - `DELETE /devices/{id}` → `is_deleted = TRUE`（仅主管，极少使用）
   - `POST /devices/{id}/retire` → `status = 'retired'`（常规操作）

3. **批量导入事务：** 使用 `async_session.begin()` 包裹整批写入，单条失败不中断，但需记录失败原因。若失败率 > 50%，建议整体回滚并提示修正后重试（可选策略）。

4. **扩展属性校验：** 创建设备时，根据 `type_id` 读取 `attribute_schema`，对 `attributes` 字段做基础 JSON Schema 校验（Pydantic `model_validator` 或 `jsonschema`）。

### 前端技术要点

1. **动态扩展属性表单：** 根据 `device_type.attribute_schema` 动态渲染表单项。例如：
   ```json
   {
     "sensitivity": { "label": "灵敏度", "type": "select", "options": ["高","中","低"] },
     "detection_area": { "label": "探测面积(㎡)", "type": "number" }
   }
   ```
   前端解析 JSON Schema 渲染对应 `el-form-item`。

2. **权限指令：** 操作按钮使用 `v-permission` 控制：
   - 新增按钮：`v-permission="['device:create']"`
   - 编辑按钮：`v-permission="['device:update']"`
   - 退役按钮：`v-permission="['device:retire']"`

4. **退役状态 UI：** 列表默认隐藏 `retired` 状态，顶部增加 `el-switch`「显示已退役」；已退役行置灰显示。

## 八、风险与依赖

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 设备扩展属性动态表单复杂度高 | F-9 延期 | 先支持 `string/number/select` 三种基础类型，复杂类型（数组/对象）延期至 P1 |
| Excel 导入大数据量内存溢出 | B-10 性能差 | 采用流式读取（`openpyxl` read_only=True），分批写入（每 100 条 commit 一次） |
| 设备历史涉及多表聚合查询慢 | B-11 响应慢 | 增加复合索引；历史数据按时间分片查询（默认最近 90 天） |
| 区域选择器数据量大 | 前端卡顿 | 组织架构树 > 200 节点时启用虚拟滚动（`el-tree-v2`） |
