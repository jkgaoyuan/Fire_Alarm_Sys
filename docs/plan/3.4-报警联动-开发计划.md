## 三、总体设计

### 3.1 数据流

```
设备模拟器 / 真实报警
        │  3.3 已生成 alarms 记录并 XADD ws:devices:stream
        ▼
linkage_engine_service.on_alarm_created(alarm)
        │  1. 按 (org_id 或其祖先, fire_type, device_type_id, alarm_type) 匹配启用中预案
        │  2. 为每个 action 生成 alarm_linkage_logs (status=pending)
        ▼
动作执行适配层 linkage_executor.execute(log)
        │  3. 更新 log.status = sent → (模拟 ack) → success/failed
        │  4. 失败时：写入 alarms (alarm_type='linkage_failed', alarm_level='critical')
        ▼
XADD ws:devices:stream { type: 'linkage_executed' / 'linkage_failed' }
        │
        ▼
前端 MonitorSocket / AlarmCenter → 联动日志抽屉 / 弹窗提示
```

**为什么动作执行要抽象适配层：** 真实消防设备协议未定（PRD 11 OQ-1：仅确定 MQTT），首版不能直接操作硬件。`linkage_executor` 接口固定为 `execute(log) -> (status, message)`，真实协议对接时仅需替换实现，不动引擎与日志表结构。

### 3.2 联动预案匹配规则

匹配键按优先级降序：
1. `org_id` 精确匹配（设备所在叶子区域）。
2. 向上递归：预案挂在祖先 `floor`/`building` 节点时，对下层设备生效（继承规则同 3.3 平面图）。
3. 按 `fire_type` 与 `trigger_device_type_id` + `trigger_alarm_type` 过滤。
4. 仅 `is_enabled=true` 的预案参与自动联动；手动执行不受启用状态限制，但需 `linkage:execute`。

> **冲突裁决**：同一报警命中多条预案时，全部执行（并集），不排他。日志按 `plan_id` 分别记录，便于追溯。

### 3.3 动作定义 JSON Schema

```json
{
  "actions": [
    {
      "action_type": "start_exhaust",
      "target_device_type_id": 6,
      "delay_seconds": 0,
      "params": {"floor": "1F", "zone": "东侧"}
    },
    {
      "action_type": "close_door",
      "target_device_type_id": 7,
      "delay_seconds": 5,
      "params": {"door_id": "D-001"}
    }
  ]
}
```

| `action_type` | 说明 | 目标设备类型 |
|---------------|------|--------------|
| `start_exhaust` | 启动排烟 | `exhaust_fan` |
| `close_door` | 关闭防火门 | `fire_door` |
| `start_lighting` | 启动应急照明 | `emergency_light` |
| `broadcast` | 疏散广播 | 无具体设备，params 存广播区域 |

首版 `delay_seconds > 0` 时仅做展示与日志标记，不阻塞执行；真实延迟调度待 Celery 引入后实现。

### 3.4 帧协议扩展

服务端 → 客户端新增 `type`：

| `type` | 触发点 | 前端动作 |
|--------|--------|----------|
| `linkage_executed` | 联动动作执行成功 | 联动日志列表刷新 / 弹窗"联动已执行" |
| `linkage_failed` | 联动动作失败或生成次级告警 | 报警中心置顶次级告警 + Notification + 弹窗提示 |
| `linkage_simulated` | 模拟触发完成 | 仅刷新日志，不生成真实告警 |

帧体示例：
```json
{
  "id": "1725864000005-0",
  "type": "linkage_failed",
  "ts": "2026-09-09T10:30:05+08:00",
  "data": {
    "alarm_id": 88,
    "linkage_log_id": 42,
    "plan_id": 3,
    "plan_name": "1F大厅火警联动",
    "action_type": "start_exhaust",
    "target_device_id": 15,
    "target_device_name": "1F东侧排烟风机",
    "status": "failed",
    "result_message": "设备离线",
    "secondary_alarm_id": 89
  }
}
```

### 4.3 模型骨架

```python
# app/models/linkage.py
class LinkagePlan(Base):
    __tablename__ = "linkage_plans"
    org_id: Mapped[int] = mapped_column(ForeignKey("organizations.id"), index=True)
    fire_type: Mapped[Optional[str]] = mapped_column(String(20))
    trigger_device_type_id: Mapped[Optional[int]] = mapped_column(
        ForeignKey("device_types.id"), index=True
    )
    trigger_alarm_type: Mapped[Optional[str]] = mapped_column(String(20))
    actions: Mapped[list[dict]] = mapped_column(JSONB, default=list)
    is_enabled: Mapped[bool] = mapped_column(default=True)

class AlarmLinkageLog(Base):
    __tablename__ = "alarm_linkage_logs"
    alarm_id: Mapped[int] = mapped_column(ForeignKey("alarms.id"), index=True)
    plan_id: Mapped[Optional[int]] = mapped_column(ForeignKey("linkage_plans.id"), index=True)
    action_type: Mapped[str] = mapped_column(String(50))
    target_device_id: Mapped[Optional[int]] = mapped_column(ForeignKey("devices.id"), index=True)
    status: Mapped[str] = mapped_column(String(20), default="pending")
```

> **不级联删除**：`Alarm` 删除时保留 `alarm_linkage_logs`（历史追溯）。`linkage_plans` 删除时，关联日志 `plan_id` 置 NULL 或保留只读（按需求选择；本计划选保留，日志不可变）。

### 后端技术要点

1. **触发时机**：联动引擎必须在 `alarms` 事务提交后调用。若在事务内调用，日志生成与广播可能在回滚后仍残留；放在 commit 后，失败仅记 warning。
2. **匹配性能**：预案数量通常 < 1000，全表过滤后在内存中按 org 树匹配即可；> 1000 时考虑在 `linkage_plans` 上建 `(org_id, trigger_device_type_id, trigger_alarm_type, is_enabled)` 复合索引。
3. **失败次级告警**：`alarm_type='linkage_failed'`，`alarm_level='critical'`，`status='pending'`，`org_id` 取原报警 `org_id`，`device_id` 取目标设备（`broadcast` 动作取原报警 `device_id`）。前端收到后按火警同级处理。
4. **模拟执行器**：首版用 `asyncio.sleep(0.1~0.3)` 模拟网络延迟，按配置比例返回 failed（默认 10%），便于验收 FR-020.1。
5. **`delay_seconds` 处理**：首版 > 0 时日志写入 `delay_seconds` 但仍立即执行，并在 `result_message` 中提示"延迟调度待实现"；避免阻塞 5 秒验收红线。

1. **DEC-005 登记**：`views/linkage/Plan.vue`、`views/linkage/PlanForm.vue` 必须在 `utils/menu.js` 的 `viewComponents` 中登记，否则菜单点击白屏。
2. **动作列表编辑**：使用 `v-for` 动态表单；`action_type` 下拉固定 4 项；`target_device_type_id` 联动过滤可用设备类型；`params` 用 JSON 文本框或简单键值对输入。
3. **二次确认**：手动执行使用 `ElMessageBox.confirm`，文案明确"是否立即执行预案 XX？此操作将产生真实联动记录"。
4. **失败弹窗**：全局弹窗组件监听 `linkage_failed`，每次失败弹出一次；避免同一报警多条失败连续刷屏（去抖 1 秒内同 `alarm_id` 合并）。
