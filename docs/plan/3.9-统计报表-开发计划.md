## 三、总体设计

### 3.1 数据流

```
业务表（devices/alarms/inspection_tasks/repair_orders/drill_events）
        │
        ├── 聚合 API ──▶ 统计看板（ECharts）
        │
        └── 导出任务 ──▶ BackgroundTasks 流式写 Excel / python-docx 写 Word
                             │
                             ▼ 完成
                       report_export_tasks.status='completed'
                             │
                             ▼ WS 推送 / 轮询下载
                       前端通知用户下载
```

### 3.2 统计口径

| 看板 | 口径 | 默认过滤 |
|------|------|----------|
| 设备完好率 | 按 `devices.status` 分组计数 | `is_deleted=false`、`status != 'retired'`、`is_drill=false` |
| 报警趋势 | 按 `alarms.created_at` 日期 + `alarm_type` 分组 | `is_drill=false` |
| 故障 TOP10 | 按 `repair_orders.device_id` 计数，取前 10 | `status='completed'`、`source != 'drill'` |
| 巡检完成率 | `completed / (completed + missed)` 按责任人/区域 | 时间范围可配 |

### 3.3 区域下钻

- 设备完好率饼图支持点击某个区域进入该区域的下级视图。
- 后端按 `organizations` 树递归计算各节点汇总；前端使用面包屑导航。

### 3.4 异步导出流程

1. 用户点击导出 → 后端创建 `report_export_tasks` 记录（状态 `pending`），返回 `task_id`。
2. `BackgroundTasks` 启动流式查询并写入 `.xlsx`/`.csv`（统计报表）或调用 `python-docx` 生成 `.docx`（演练报告）。
3. 前端**轮询为主**：每 2 秒调用 `GET /reports/export/{task_id}/status`，最多 5 分钟；WS `report_export_completed` 事件作为体验增强（用户离线时通知丢失可接受）。
4. 状态为 `completed` 时调用 `GET /reports/export/{task_id}/download` 下载文件；状态为 `failed` 时提示用户重试。
5. 文件保存于本地卷（首版），后续可扩展 MinIO。

> **任务丢失容忍**：uvicorn 重启可能导致 BackgroundTasks 中的导出任务丢失，首版不实现任务恢复；任务失败后由用户重试。3.10 评估是否引入持久化任务队列（如 Celery）。

### 4.2 模型骨架

```python
# app/models/report_export.py
class ReportExportTask(Base):
    __tablename__ = "report_export_tasks"
    task_no: Mapped[str] = mapped_column(String(50), unique=True)
    task_type: Mapped[str] = mapped_column(String(50))
    status: Mapped[str] = mapped_column(String(20), default="pending")
    file_path: Mapped[Optional[str]] = mapped_column(String(500), nullable=True)
    file_name: Mapped[Optional[str]] = mapped_column(String(200), nullable=True)

    error_message: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    created_by: Mapped[int] = mapped_column(ForeignKey("users.id"))
    completed_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
```

### 后端技术要点

1. **统计查询优化**：设备/报警聚合使用 `count(*)` + `GROUP BY`；大数据量用物化视图或缓存（首版直接查询，>3 秒时加缓存）。
2. **区域下钻**：后端按 `organizations` 树计算可见节点；前端传入 `org_id` 时返回该节点及子节点汇总。
3. **异步导出流式写**：使用 `openpyxl` 的 `write_only=True` 模式，分批查询（每次 1000 行），避免内存溢出。
4. **Word 演练报告生成**：使用 `python-docx` 生成结构化文档，内容沿用 3.8 演练评估报告字段（演练基本信息、评估项打分、问题与改进、总体评估、照片附件）；图片通过 `add_picture` 嵌入，统一 A4 版面。导出任务 `task_type='drill_report'`，由 3.8 演练报告详情页调用统一 `POST /reports/export` 触发。

| OQ-4 | Word 导出权限 | **仅消防主管**可导出演练报告 Word，复用 `statistics:export` 权限码 | 演练归档属管理动作 |
| OQ-5 | Word 是否走异步 | **始终走异步**，统一复用异步框架 | 保持代码一致性，便于任务列表统一查看 |
| OQ-6 | BackgroundTasks 任务丢失 | **首版不实现恢复机制**；任务失败标记 `failed`，用户重试即可；3.10 评估持久化队列 | 首版规模小，重试成本低于 MQ 成本 |
| OQ-7 | Celery 引入决策 | **正式宣布 3.9 不引入 Celery**，评估推迟到 3.10 | 已写入偏离 C-1 |

### B. 产品缺口决议（PRD 未明处，本计划定稿）

| 缺口 | 决议 | 理由 |
|------|------|------|
| FR-052 "消息通知下载" 实现路径 | **轮询为主、WS 为辅**；离线通知丢失可接受（任务列表仍可查看历史） | 轮询可靠性高；WS 仅作体验增强 |
| 导出中心入口位置 | 作为 `statistics:report` 父菜单下的子菜单项，权限码 `statistics:export`（仅主管可见） | 符合 RBAC 菜单层级规范 |
| Word 演练报告模板定制 | **首版硬编码模板**（不可定制），后续迭代支持模板上传 | 首版聚焦功能交付 |
| 演练报告 Word 导出触发入口 | 由 3.8 演练报告详情页点击"导出 Word"按钮触发，调用统一 `POST /reports/export`（`task_type='drill_report'`） | 复用异步导出框架，统一任务列表 |
| 导出任务失败处理 | 状态变为 `failed`，前端提示用户"导出失败，点击重试"；后端保留 `error_message` 供排查 | 首版不实现自动重试 |
| Word 导出文件命名 | `演练报告-{drill_name}-{YYYYMMDD}.docx`（Excel 沿用类似规则） | 便于用户本地管理 |
