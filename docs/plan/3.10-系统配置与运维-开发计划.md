## 三、总体设计

### 3.1 数据流

```
管理员配置
   ├── 数据字典 ──▶ dictionaries 表 ──▶ 前端下拉框动态渲染
   │
   ├── 通知渠道 ──▶ notification_configs 表 ──▶ 3.5/3.4 通知服务读取 SMTP
   │                                          └── 触发邮件发送
   │
   └── 清理策略 ──▶ lifespan asyncio 后台任务 ──▶ 每日清理 audit_logs / Redis Stream
```

### 3.2 数据字典设计

| 字段 | 说明 |
|------|------|
| `dict_type` | 字典类型：`device_type` / `alarm_level` / `fault_reason` / `drill_type` / `inspection_cycle` 等 |
| `dict_code` | 字典编码（程序中使用） |
| `dict_name` | 显示名称 |
| `sort_order` | 排序 |
| `is_enabled` | 是否启用 |
| `extra` | 扩展 JSON（如颜色、图标） |

**使用方式：**
- 后端：固定枚举仍保留在代码中（保证状态机安全）；新增类型通过字典扩展。
- 前端：下拉框组件统一调用 `GET /api/v1/config/dictionary/{dict_type}` 渲染。

### 3.3 通知渠道配置

| 配置项 | 说明 |
|--------|------|
| `smtp_host` / `smtp_port` / `smtp_user` / `smtp_password` | SMTP 服务器 |
| `smtp_tls` | 是否 TLS |
| `from_address` | 发件人 |
| `notify_on_alarm_timeout` | 超时未确认是否邮件通知主管 |
| `notify_on_linkage_failed` | 联动失败是否邮件通知主管 |

邮件发送采用 `aiosmtplib` 异步发送；失败时只记录日志，不阻塞主流程。

### 3.4 日志清理策略

- 每日 02:00 执行 lifespan asyncio 后台任务。
- 删除 `audit_logs` 中 `created_at < NOW() - INTERVAL '180 days'` 的记录。
- 裁剪 Redis Stream `ws:devices:stream` 至最近 7 天或最近 10000 条（取较小者）。
- 清理结果写入应用日志。

### 4.2 新增表 `notification_configs`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGSERIAL | PK | |
| config_key | VARCHAR(100) | UNIQUE, NOT NULL | 配置键 |
| config_value | TEXT | | 配置值（敏感值如密码可加密） |
| description | VARCHAR(255) | | 描述 |
| updated_by | BIGINT | FK → users.id | |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | |

### 4.3 模型骨架

```python
# app/models/config.py
class Dictionary(Base):
    __tablename__ = "dictionaries"
    dict_type: Mapped[str] = mapped_column(String(50), index=True)
    dict_code: Mapped[str] = mapped_column(String(50))
    dict_name: Mapped[str] = mapped_column(String(100))
    sort_order: Mapped[int] = mapped_column(default=0)
    is_enabled: Mapped[bool] = mapped_column(default=True)
    extra: Mapped[dict] = mapped_column(JSONB, default=dict)

class NotificationConfig(Base):
    __tablename__ = "notification_configs"
    config_key: Mapped[str] = mapped_column(String(100), unique=True)
    config_value: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    description: Mapped[Optional[str]] = mapped_column(String(255), nullable=True)
    updated_by: Mapped[Optional[int]] = mapped_column(ForeignKey("users.id"), nullable=True)
```

### 后端技术要点

1. **字典缓存**：字典数据变化不频繁，使用内存缓存（TTL 5 分钟），减少数据库查询。
2. **邮件敏感信息**：SMTP 密码可加密存储（AES-256-GCM）；测试接口不返回密码。
3. **清理任务幂等**：基于时间戳删除，多次执行结果一致。
4. **配置热生效**： lifespan 后台任务读取最新配置，无需重启服务。

## 十一、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| SMTP 配置错误导致邮件发送失败 | 通知失效 | 测试接口验证；失败只记日志不抛异常 |
| 字典动态扩展与代码硬编码枚举冲突 | 状态机异常 | 核心状态机仍用代码枚举；字典只用于展示/筛选 |
| 清理任务误删 | 数据丢失 | 严格按时间戳删除；生产前先在测试环境跑 |
| 多实例同时执行清理 | 资源竞争 | 基于数据库时间戳幂等；冲突无严重后果 |
