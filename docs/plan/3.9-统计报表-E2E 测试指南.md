# 3.9 统计报表模块 E2E 测试指南

## 📋 概述

本指南说明如何运行 3.9 统计报表模块的端到端 (E2E) 测试。

## 🧪 测试文件

E2E 测试位于:
- `backend/tests/test_statistics_e2e_integration.py` - 3 条核心 E2E 用例

## 🚀 运行方式

### 方式一：本地内存数据库测试（快速验证）

```bash
cd backend
python -m pytest tests/test_statistics_e2e_integration.py -v --tb=short
```

**注意**: 当前存在 SQLAlchemy asyncio 会话管理问题，建议使用方法二。

### 方式二：真实容器环境（推荐✓）

1. **启动数据库和 Redis 容器**:
   ```bash
   cd ..
   docker-compose up -d postgres redis
   ```

2. **初始化数据库**:
   ```bash
   cd backend
   python scripts/init_data.py
   ```

3. **启动应用服务器**:
   ```bash
   uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
   ```

4. **设置环境变量并运行 E2E 测试**:
   ```bash
   export E2E_BASE_URL=http://localhost:8000/api/v1
   python -m pytest tests/e2e/test_statistics_e2e.py -v --tb=short
   ```

## 📝 测试场景

### 1. test_e2e_export_workflow - 完整导出流程
- 创建 Excel 导出任务
- 轮询任务状态直到完成
- 下载生成的文件
- 验证文件大小和内容

### 2. test_e2e_permission_denial - 权限验证
- 使用只有 view 权限的用户
- 尝试创建导出任务
- 验证返回 403 Forbidden

### 3. test_e2e_task_pagination - 分页查询
- 创建 5 个导出任务
- 查询第一页（page_size=2）
- 验证总数和记录数
- 查询第二页验证分页逻辑

## 🐛 已知问题

### SQLAlchemy Async Session 管理

本地测试中遇到的 `MissingGreenlet` 错误是因为:
- FastAPI ASGI transport 测试客户端使用异步 session
- 但 fixtures 中的某些操作是同步的
- 导致 greenlet_spawn 未调用

**临时解决方案**: 
- 使用方法二（真实容器环境）
- 或者等待 conftest.py 的 session 管理优化

## ✅ 验收标准

E2E 测试需要通过以下标准才算完成:
1. ✅ 所有测试在真实容器环境中运行通过
2. ✅ 连续两次运行结果一致
3. ✅ 无外部依赖（不污染全局数据）
4. ✅ 测试后清理干净（可选）
