## 三、总体设计

### 3.1 数据流

```
故障来源
   ├── 巡检异常（inspection_records.result='abnormal'）
   ├── 报警/监控发现故障（alarms.alarm_type='fault'）
   └── 人工报修
            │
            ▼ 创建 repair_orders (status='pending')
            │
            ├── 主管派单 ──▶ status='assigned', repairer_id=xxx
            │
            ├── 维修中 ──▶ status='repairing'
            │
            ├── 完成填报 ──▶ status='pending_accept', repair_result, parts 等
            │
            ├── 验收通过 ──▶ status='completed' ──▶ devices.status='normal'
            │
            └── 验收不通过 ──▶ status='returned' ──▶ 重新维修
```

### 3.2 状态机

```
                    ┌─────────────┐
                    │   pending   │
                    └──────┬──────┘
                           │ assign
                           ▼
                    ┌─────────────┐
                    │   assigned  │
                    └──────┬──────┘
                           │ start
                           ▼
                    ┌─────────────┐
                    │  repairing  │
                    └──────┬──────┘
                           │ complete
                           ▼
                 ┌─────────────────────┐
                 │    pending_accept   │
                 └──────────┬──────────┘
                            │
              ┌─────────────┴─────────────┐
              │ accept                      │ reject
              ▼                             ▼
       ┌─────────────┐              ┌─────────────┐
       │  completed  │              │   returned  │
       └─────────────┘              └──────┬──────┘
                                          │ re-repair
                                          ▼
                                   ┌─────────────┐
                                   │  repairing  │
                                   └─────────────┘
```

- `completed` 为终态，不可再修改。
- `returned` 后回到 `repairing`，可多次循环。
- 状态变更由特定接口触发，每个接口校验前置状态。

### 3.3 创单入口

1. **手动创建**：维修/主管在工单列表页点击"新建"，选择设备、填写故障描述。
2. **巡检异常快捷创建**：3.6 填报 abnormal 后，跳转创建页并携带 `device_id` 与 `source='inspection'`、`source_id`。
3. **报警关联创建**：报警详情页提供"创建维修工单"按钮，携带 `alarm_id`。

### 3.4 配件记录格式

```json
[
  {"name": "烟感探头", "model": "XXX", "quantity": 1, "unit": "个"}
]
```

首版以 JSONB 存储，不做库存扣减。

### 4.2 模型骨架

```python
# app/models/repair.py
class RepairOrder(Base):
    __tablename__ = "repair_orders"
    order_no: Mapped[str] = mapped_column(String(50), unique=True)
    device_id: Mapped[int] = mapped_column(ForeignKey("devices.id"), index=True)
    alarm_id: Mapped[Optional[int]] = mapped_column(ForeignKey("alarms.id"), index=True, nullable=True)
    source: Mapped[Optional[str]] = mapped_column(String(20), nullable=True)
    source_id: Mapped[Optional[int]] = mapped_column(BigInteger, nullable=True)
    fault_desc: Mapped[str] = mapped_column(Text)
    status: Mapped[str] = mapped_column(String(20), default="pending")
    reporter_id: Mapped[Optional[int]] = mapped_column(ForeignKey("users.id"), nullable=True)
    repairer_id: Mapped[Optional[int]] = mapped_column(ForeignKey("users.id"), index=True, nullable=True)
    assigned_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
    completed_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
    repair_result: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
    parts: Mapped[list[dict]] = mapped_column(JSONB, default=list)
    acceptor_id: Mapped[Optional[int]] = mapped_column(ForeignKey("users.id"), nullable=True)
    accepted_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
    accept_remark: Mapped[Optional[str]] = mapped_column(Text, nullable=True)
```

### 后端技术要点

1. **状态流转强校验**：每个动作接口校验当前状态，非法状态返回 409。
2. **编号生成**：使用日期 + 当日序号；并发时通过数据库唯一约束重试。
3. **数据权限**：工单列表通过 `device.org_id` 过滤；`self` 范围降级为 `dept`。
4. **完成恢复设备状态**：在 `accept` 事务内同时更新 `devices.status='normal'`；若关联报警仍存在且为 `pending`，可自动调用复位逻辑（需确认业务规则）。
5. **来源追溯**：`source`/`source_id` 用于从巡检/报警跳转回工单。

## 十一、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 验收不通过后循环次数无上限 | 工单长期挂起 | UI 显示退回次数；主管可强制关闭 |
| 维修完成后设备仍被报警系统再次标记故障 | 状态冲突 | 以报警/上报状态为准；维修恢复只在无新报警时生效 |
| 多来源创单字段不一致 | 数据混乱 | 统一 `source`/`source_id` 枚举 |
| 维修统计口径争议 | 报表不一致 | 平均维修时长 = completed_at - created_at；只统计 completed 工单 |
